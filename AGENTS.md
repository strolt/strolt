## Known Pitfalls

- **swaggo vs gofmt conflict on swagger annotation blocks.** A doc comment consisting only of `@`-annotation lines cannot satisfy both formatters: swaggo wants tab-indented annotations, while gofmt's doc-comment normalizer strips the indentation back. Use the pattern `// <funcName> godoc`, then a blank `//` line, then tab-indented `//\t@...` annotation lines — both formatters accept it.
- **Local `replace` directives in `go.mod` are intentional.** The monorepo links `shared` via `replace github.com/strolt/strolt/shared => ../../shared`; the `gomoddirectives` linter is configured with `replace-local: true` in each module's `.golangci.yaml`. Do not remove the replace directives or the setting.
- **golangci-lint caps its output by default.** Use `--max-issues-per-linter 0 --max-same-issues 0` to see the full issue list; otherwise consecutive runs show different subsets.
- **restic in `docker/strolt/Dockerfile` comes from official GitHub releases, not apk.** Alpine packages lag behind restic upstream (3.23 and even edge ship 0.18.x while upstream is 0.19+). The release binaries are static, so restic must stay excluded from the `ldd` sanity-check stage; do not "simplify" back to `apk add restic` or it silently downgrades.
- **e2e database containers must use the official testcontainers modules' wait strategies.** The postgres/mariadb image entrypoints start a temporary server during init and then restart it; a plain `wait.ForSQL` probe races with that restart and makes the suite flaky. Use `postgres.Run` + `BasicWaitStrategies()`, `mariadb.Run`, etc. (see `apps/strolt/e2e/containers_test.go`).
- **MySQL 8+ support needs `mariadb-connector-c` and the `tls` driver option.** The client auth plugins (`caching_sha2_password.so`) live in the `mariadb-connector-c` apk package — `mariadb-client` alone does not pull it in; the Dockerfile copies `/usr/lib/mariadb/plugin/`. The MariaDB 11.4 client also verifies TLS certificates by default and only auto-validates against MariaDB servers, so connecting to MySQL with an auto-generated certificate requires `tls: skip-verify` in the mysql source driver config.
- **restic retries missing-backend errors for up to ~15 minutes.** A backup/snapshots call against a repository whose S3 bucket does not exist hangs in restic's retry loop, not in strolt. In e2e negative scenarios, point destinations at an existing repository or use `operationMode: copy` so the failing dump aborts before restic starts.
- **`restic forget <id>` exits 0 when the snapshot does not exist.** It only prints `Ignoring "<id>": no matching ID found for prefix` on stderr, so a forget that removed nothing looks like success. The restic driver treats that warning as an error (`isSnapshotNotFound` in `apps/strolt/internal/driver/destination/restic/forget.go`); keep the check when touching that code.
- **`--no-lock` is incompatible with a real `forget`.** restic aborts with `Fatal: --no-lock is only applicable in combination with --dry-run for forget command`, which breaks both prune and forget for destinations configured with `no-lock: true`. Commands that must hold a repository lock build their flags with `getGlobalFlagsWithLock()` instead of `getGlobalFlags()`; the dry-run prune keeps the flag because restic allows it there.
- **The restic driver builds its process environment from scratch.** `getEnv()` returns a fixed list instead of extending `os.Environ()`, so a `RESTIC_*`/cloud variable exported around strolt never reaches restic. Anything the typed `Env` fields do not cover has to go through `config.env_extra`, whose pairs are appended last (os/exec keeps the last occurrence of a duplicated variable, so they also override `env`). It sits under `config` and not `env` because `config.DriverDestinationConfig.Env` is a `map[string]string` — a nested mapping under `env:` fails to parse with `cannot unmarshal !!map into string`.
- **Concurrent strolt processes share the data directory.** Temp workdir GC (`dir.RemoveTempDirectories`) runs only on daemon startup; do not re-add it to every CLI invocation (`cmd_root.Execute`) or parallel strolt runs (daemon + CLI in one container, parallel e2e suites) will wipe each other's in-flight work directories — restic then dies with `getwd: no such file or directory`.
- **`apps/stroltm/ui` has TWO pnpm lockfiles.** It is a member of the root workspace (root `pnpm-lock.yaml`) AND a standalone project for the Docker build and Makefile targets, with its own `pnpm-lock.yaml` plus a settings-only `pnpm-workspace.yaml` (no `packages` key) that carries `allowBuilds`/`minimumReleaseAgeExclude`/`trustLockfile` for that context. After changing `ui/package.json`, update both: `pnpm install` at the root and `cd apps/stroltm/ui && pnpm install --lockfile-only`. pnpm 11.5+ applies a default 24h `minimumReleaseAge` even standalone, so freshly published `@shibanet0/*` packages fail without the exclude.
- **pnpm keeps stale subdependency resolutions after a parent bump.** antd 6.4.x needs `@rc-component/util` >= 1.10 (root exports of `raf`/`useLayoutEffect`) but declares `^1.4.0`, so an old locked 1.6/1.9 survives an antd bump and rolldown fails with `MISSING_EXPORT`. Fix with `pnpm -r update "@rc-component/util"` at the root and the same `--lockfile-only` update in `apps/stroltm/ui`.
- **Do not use a bare `"*"` catch-all in tsconfig `paths`.** vite-tsconfig-paths applies it to absolute ids of virtual modules too (vanilla-extract dies with `No CSS for file: <src>//abs/path`); enumerate the `src/` top-level directories explicitly instead.
- **Official node Docker images ship no `linux/arm/v7` variant.** Release builds target amd64/arm/v7/arm64, so any stage based on a node image must be pinned to `--platform=$BUILDPLATFORM` (its artifacts — UI dist, generated code — are architecture-independent anyway). PR builds only cover amd64 and will not catch this; the same applies to the swagger stage.
- **The generated openapi client forces two strictness opt-outs.** `typescript-axios` output uses constructor parameter properties and non-exact optional assignments, so `erasableSyntaxOnly` and `exactOptionalPropertyTypes` stay `false` in `apps/stroltm/ui/tsconfig.json` until the generator complies. The tsconfig is strict JSON (`yq-json` fixer) — no comments allowed.
